# webtest-03-case-design

## 输入

- 输入文件：`webtest/02-business-flow/` 目录下最新的 `*-业务梳理.md` 文件
- 关联文件：`webtest/01-system-explore/` 目录下的探索报告（用于事实追溯）

## 任务

基于业务流程和已验证页面事实设计 Web 测试用例，不生成自动化代码。

## 执行流程

### 1. 风险核对

按以下维度逐一核对风险：

| 维度 | 检查内容 |
|------|----------|
| 正向 | 核心业务路径的完整性 |
| 异常 | 错误处理与容错机制 |
| 边界 | 输入值、数据量、时间等边界条件 |
| 权限 | 角色权限与访问控制 |
| 状态 | 系统状态迁移与状态依赖 |
| 配置 | 环境配置与系统参数 |
| 数据一致性 | 前后端数据同步与一致性 |
| 网络与加载异常 | 超时、断网、慢加载等网络场景 |

### 2. 测试点设计

测试点负责覆盖与追溯：
- 每个测试点关联到业务流程的具体步骤
- 每个测试点明确覆盖的风险维度
- 建立测试点与业务流程的双向追溯关系

### 3. 场景设计

场景围绕可独立执行的用户目标聚合相关检查点：
- 每条场景包含：

| 字段 | 说明 |
|------|------|
| 场景编号 | 唯一标识 |
| 场景名称 | 简要描述 |
| 来源 | 关联的业务流程步骤 |
| 角色 | 执行用户角色 |
| 前置条件 | 执行前的系统状态要求 |
| 测试数据 | 需要准备的数据 |
| 用户动作 | 详细的操作步骤 |
| 可观察预期 | 预期的页面表现与状态变化 |
| 业务对象识别方式 | 如何识别和定位目标对象 |
| 清理责任 | 测试后的数据清理方案 |

### 4. 探索性场景

没有已验证事实支持的内容只能进入探索性场景：
- 写明候选预期（非确定预期）
- 写明验证路径（如何确认预期是否正确）
- 标记为探索性场景，与正式场景区分

### 5. 质量检查

最后检查：
- 测试点与场景的双向追溯完整性
- 重复内容识别与去重
- 跨场景依赖关系梳理
- 覆盖率统计

## 约束规则

- 没有已验证事实支持的内容只能进入探索性场景
- 不生成自动化代码
- 每个场景必须可独立执行
- 保持测试点与场景的双向追溯

## 输出

生成以下三个文件，保存到 `webtest/03-case-design/` 目录：

### 文件1：测试点

命名格式：`[系统功能]-测试点.md`

内容：
- 测试点清单（编号、描述、覆盖维度、追溯关系）
- 覆盖率统计

### 文件2：需求理解

命名格式：`[系统功能]-需求理解.md`

内容：
- 业务目标理解
- 关键业务规则
- 风险识别结果
- 测试策略说明

### 文件3：用例

命名格式：`[系统功能]-用例.md`

内容：
- 正式测试场景清单
- 探索性测试场景清单
- 测试数据需求
- 环境准备要求

## Skill 目录结构

```
webtest-03-case-design/
├── SKILL.md           # 本文件
├── templates/         # 测试点模板、需求理解模板、用例模板
├── examples/          # 优秀测试设计文档示例
├── scripts/           # 辅助脚本（用例覆盖率统计等）
└── references/        # 测试设计方法论参考文档
```

### templates/

- `测试点模板.md` — 测试点清单的标准结构模板
- `需求理解模板.md` — 需求理解文档的标准结构模板
- `用例模板.md` — 测试用例的标准记录格式（含正式场景与探索性场景）

### examples/

- `优秀测试点示例.md` — 一份完整的高质量测试点清单范例
- `优秀用例示例.md` — 一份完整的高质量测试用例文档范例

### scripts/

- 可存放覆盖率统计、用例去重检查等脚本

### references/

- 可存放等价类划分、边界值分析、测试设计方法论等参考文档

## 使用方式

用户调用 `/webtest-03-case-design` 即可，Skill 会自动读取上一步的输出文件。
