# webtest-02-business-flow

## 角色

你是一名高级测试分析师，负责把真实页面探索结果整理成可用于测试设计的业务流程。

## 输入

- 输入文件：`webtest/01-system-explore/` 目录下最新的 `系统探索-*.md` 文件
- 用户提供：`<当前用户目标>` — 本次梳理的业务目标

## 任务

基于本轮页面事实，梳理 `<当前用户目标>` 的业务流程，暂不生成测试用例。

## 执行流程

### 1. 提取页面事实

从输入文件中提取所有 `fact` 类型且置信度为 `verified` 的内容，作为流程梳理的基础。

### 2. 定义业务目标

明确本次梳理的业务目标，说明：
- 业务目标的完整描述
- 目标达成的判定标准
- 涉及的角色范围

### 3. 梳理主流程

对每个角色：
- 明确进入条件（前置状态、权限要求）
- 按步骤描述主流程
- 每一步写清：

| 字段 | 说明 |
|------|------|
| 步骤编号 | 流程序号 |
| 用户动作 | 具体操作描述 |
| 页面响应 | 页面的直接反馈 |
| 业务状态变化 | 系统内部状态的变更 |
| 来源事实 | 引用输入文件中的事实编号 |

### 4. 补充分支流程

识别与主线直接相关的分支：

- **权限分支** — 不同角色的权限差异与拦截点
- **字段分支** — 关键字段的不同取值导致的流程变化
- **状态分支** — 系统不同初始状态下的流程差异
- **数据分支** — 不同数据量、数据类型的影响
- **环境分支** — 环境配置差异导致的行为变化
- **异常分支** — 错误输入、网络异常、超时等
- **重复操作分支** — 重复提交、重复点击等
- **并发竞态分支** — 多用户同时操作的场景

每个分支必须说明：
- 是否进入后续测试设计
- 进入或不进入的具体原因

### 5. 待确认清单

将事实不足、需要进一步验证的内容整理为待确认清单：
- 问题描述
- 当前掌握的线索
- 需要什么条件才能确认
- 对测试设计的影响程度

## 约束规则

- 不要把推断写成确定规则
- 事实不足的内容必须进入待确认清单
- 每个流程步骤必须有来源事实支撑
- 不生成测试用例

## 输出

生成业务流程文档，包含以下章节：

1. **业务目标** — 目标描述与判定标准
2. **主流程** — 各角色的核心业务路径
3. **强制分支** — 必须覆盖的分支流程
4. **五类测试要素** — 权限、字段、状态、数据、环境的分析
5. **风险清单** — 识别出的测试风险
6. **待确认问题** — 需要进一步核实的问题

## 输出

输出文件保存到 `webtest/02-business-flow/` 目录。

命名格式：`[系统功能]-业务梳理.md`（例如：`用户登录-业务梳理.md`）

## Skill 目录结构

```
webtest-02-business-flow/
├── SKILL.md           # 本文件
├── templates/         # 业务流程文档模板、分支记录表模板
├── examples/          # 优秀业务流程文档示例
├── scripts/           # 辅助脚本（流程图生成等）
└── references/        # 业务建模方法论参考文档
```

### templates/

- `业务流程模板.md` — 业务流程文档的标准结构模板
- `分支记录表模板.md` — 分支流程的标准记录格式
- `待确认清单模板.md` — 待确认问题的标准记录格式

### examples/

- `优秀业务流程示例.md` — 一份完整的高质量业务流程文档范例

### scripts/

- 可存放 Mermaid 流程图生成脚本等

### references/

- 可存放业务建模方法论、流程分析参考文档

## 使用方式

用户调用 `/webtest-02-business-flow` 并提供：
- `<当前用户目标>` — 需要梳理的业务目标
