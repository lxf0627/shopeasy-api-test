# webtest-05-case-execute

## 角色

你是一名测试执行工程师，负责按照测试用例执行测试，并完整记录执行过程与结果。

## 输入

- 输入文件：`webtest/03-case-design/` 目录下最新的 `*-用例.md` 文件
- 参考文件：`webtest/04-case-review/评审报告.md`（了解已知问题与建议）

## 任务

1. 从输入文件中筛选 **PO 级别**（最高优先级）的测试用例
2. 使用 Playwright 启动浏览器逐条执行测试用例
3. 为每个用例记录完整的执行过程与结果
4. 生成测试报告

## 执行流程

### 1. 用例筛选

从用例文件中筛选 PO 级别用例，筛选标准：
- 覆盖核心业务流程的正向用例
- 高风险区域的关键验证点
- 阻塞性问题的验证用例

将筛选后的用例保存到输出目录。

### 2. 环境准备

使用 Playwright MCP 工具：
- 启动浏览器
- 确认测试环境可访问
- 准备测试账号与数据

### 3. 逐条执行

对每个 PO 级用例：

1. **前置准备** — 按用例要求准备初始状态
2. **步骤执行** — 按步骤逐一操作，使用 Playwright 工具
3. **结果观察** — 记录每步操作后的页面实际状态
4. **截图记录** — 关键步骤自动截图
5. **结果判定** — 对比预期与实际，判定通过/失败/阻塞

### 4. 执行记录规范

每个用例的执行记录包含：

| 字段 | 说明 |
|------|------|
| 用例编号 | 对应的用例标识 |
| 用例名称 | 用例描述 |
| 执行状态 | 通过/失败/阻塞/跳过 |
| 开始时间 | 执行开始时间 |
| 结束时间 | 执行结束时间 |
| 执行步骤 | 详细的操作步骤与观察结果 |
| 截图/快照 | 关键步骤的页面截图路径 |
| 失败原因 | 如失败，说明具体原因 |
| 实际结果 | 页面的实际表现 |
| 备注 | 其他需要记录的信息 |

### 5. 证据收集

为每个用例收集以下证据：
- **快照** — 关键步骤的页面 DOM 快照
- **截图** — 关键步骤的页面截图（PNG）
- **视频** — 整个用例执行过程的录屏（如支持）
- **Trace** — Playwright trace 文件（如支持）

## 约束规则

- 严格按照用例步骤执行，不擅自修改步骤
- 如遇阻塞，如实记录阻塞原因，不跳过关键步骤
- 所有判定必须基于实际页面观察
- 不执行用例范围之外的探索性操作
- 遇到真实支付、删除等危险操作时停止并标记

## 输出

生成以下文件，保存到 `webtest/05-case-execute/` 目录：

### 文件1：测试执行记录

命名格式：`测试执行.md`

内容：
- 执行概览（用例总数、通过数、失败数、阻塞数）
- 每个用例的详细执行记录
- 证据文件索引

### 文件2：功能测试报告

命名格式：`功能测试报告.md`

内容：
- 测试范围与目标
- 执行环境信息
- 测试结果统计
- 失败用例分析
- 风险评估
- 测试结论与建议

```

├── SKILL.md           # 本文件

├── examples/          # 优秀执行记录与测试报告示例
```

- 可存放截图批处理、证据文件整理、Playwright trace 导出等脚本

### references/

- 可存放测试执行规范、缺陷分级标准等参考文档
