# 用户下单流程 - 业务梳理

**梳理日期**：2026-09-14
**业务目标**：用户下单流程（登录→商品详情→选择规格→加入购物车→购物车结算→创建订单→查询订单）
**测试环境**：http://localhost:5173
**输入文件**：`webtest/01-system-explore/系统探索-2026-09-14.md`

---

## 1. 业务目标

### 1.1 目标描述

用户能够完成从商品浏览到订单创建的完整购物流程，包括：
1. 用户登录系统
2. 浏览商品详情
3. 选择商品规格
4. 将商品加入购物车
5. 在购物车结算
6. 创建订单
7. 查询订单状态

### 1.2 目标达成判定标准

| 序号 | 判定标准 | 来源 |
|------|----------|------|
| 1 | 能完成从商品选择到创建订单 | shop.txt |
| 2 | 能在系统中查询到新建订单 | shop.txt |
| 3 | 能够登录注册成功 | shop.txt |
| 4 | 商品选择不同的规格后价格显示正确 | shop.txt |
| 5 | 详情页数据显示正常 | shop.txt |

### 1.3 涉及角色范围

| 角色 | 账号 | 用途 |
|------|------|------|
| 管理员 | admin | 已完成探索，可用于前台下单测试 |
| 用户1 | buyer1 | 待测试，普通用户角色 |
| 用户2 | buyer2 | 待测试，普通用户角色 |
| 禁用用户 | disabled_user | 待测试，验证禁用状态 |

### 1.4 操作边界

- ✅ 可以创建演示订单
- ✅ 使用"货到付款"支付方式
- ✅ 走"加入购物车后结算"流程
- ❌ 不进入支付宝、微信、银行卡等第三方真实支付
- ❌ 默认不使用优惠券
- ❌ 不修改账号资料

## 2. 主流程

### 2.1 用户下单主流程

基于已验证的事实（fact），梳理用户下单的核心路径：

#### 步骤1：访问首页

| 字段 | 内容 |
|------|------|
| 步骤编号 | S001 |
| 用户动作 | 在浏览器输入 http://localhost:5173 访问首页 |
| 页面响应 | 显示商品分类（全部、手机数码、电脑办公、家用电器、服装鞋包、食品饮料、图书文具）、搜索框、排序选项（默认、销量、价格↑、价格↓、评分）、商品列表（12个商品/页，共3页） |
| 业务状态变化 | 无 |
| 来源事实 | F001, F002, F003, F004, F005, F006 |

#### 步骤2：选择商品

| 字段 | 内容 |
|------|------|
| 步骤编号 | S002 |
| 用户动作 | 点击商品卡片（如"iPhone 15 Pro Max"） |
| 页面响应 | 跳转到商品详情页 `/product/{id}`，显示商品图片（4张）、名称、描述、价格（¥9999/¥10999）、销量（2582）、库存（98）、评分（⭐4.8）、分类（手机数码） |
| 业务状态变化 | 无 |
| 来源事实 | F010 |

#### 步骤3：选择商品规格

| 字段 | 内容 |
|------|------|
| 步骤编号 | S003 |
| 用户动作 | 选择内存规格（256GB/512GB/1TB）和颜色规格（原色钛金属/蓝色钛金属/白色钛金属） |
| 页面响应 | 1. 选择部分规格时，"加入购物车"按钮仍禁用<br>2. 选择所有规格后，显示"已选: 256GB / 原色钛金属"<br>3. "加入购物车"按钮启用<br>4. 库存从98变为30（特定规格组合的库存） |
| 业务状态变化 | 系统记录已选规格组合，更新为该规格组合的库存数量 |
| 来源事实 | F011, F012, F013, F014 |

#### 步骤4：加入购物车

| 字段 | 内容 |
|------|------|
| 步骤编号 | S004 |
| 用户动作 | 点击"加入购物车"按钮 |
| 页面响应 | 按钮变为active状态（无明显成功提示） |
| 业务状态变化 | 商品添加到购物车，购物车数量更新 |
| 来源事实 | F015 |

#### 步骤5：查看购物车

| 字段 | 内容 |
