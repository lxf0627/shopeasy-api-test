## 一、业务目标理解

### 核心目标

管理员通过后台商品管理模块，对商品进行全生命周期管理（新增→编辑→上下架），确保商品数据准确，控制商品在前台的可见状态。

### 目标达成的5项标准

| 编号 | 标准 | 来源 |
|------|------|------|
| G-1 | 管理员能在商品列表中查看所有商品的基本信息（ID/名称/分类/规格/价格/库存/销量/状态） | F-06 |
| G-2 | 管理员能新增商品（含基础信息、图片、规格），新增商品应出现在前台 | F-10, F-11 |
| G-3 | 管理员能编辑已有商品的全部信息（含规格组合的价格/原价/库存） | F-12~F-15 |
| G-4 | 管理员能通过上下架控制商品在前台的可见性，状态即时生效 | F-20, F-21 |
| G-5 | 管理员能通过关键词搜索和状态筛选快速定位商品 | F-17~F-19 |

### 功能边界

| 包含 | 不包含（当前范围外） |
|------|-------------------|
| 商品列表查看 | 订单管理 |
| 商品新增（含图片、规格） | 用户管理 |
| 商品编辑（含图片、规格） | 评价管理 |
| 商品上下架 | 分类管理的增删改操作 |
| 搜索和状态筛选 | 前台商品展示与购买流程 |
| 分页浏览 | API 层面测试 |

## 三、风险识别结果

### 高风险（🔴）

| 风险ID | 风险名称 | 风险描述 | 测试策略 |
|--------|---------|---------|---------|
| R-01 | 下架无二次确认 | 点击"下架"直接执行，误操作可立即影响前台销售 | 设计专门场景验证当前行为，标注为与文档矛盾的待确认项 |
| R-02 | 无删除商品功能 | 列表无"删除"按钮，可能功能缺失或概念混淆 | 设计探索性场景，在编辑弹窗中查找是否有删除入口 |

### 中风险（🟡）

| 风险ID | 风险名称 | 风险描述 | 测试策略 |
|--------|---------|---------|---------|
| R-03 | 规格组合一致性 | 删除规格值后组合表是否同步更新未验证 | 设计编辑场景，验证规格增删后组合表的变化 |
| R-04 | 分类关联完整性 | 删除有商品关联的分类时的行为未知 | 作为探索性场景，先验证再确定预期 |
| R-05 | 图片最少1张约束 | 编辑时可删除图片，删除最后一张的行为未知 | 设计边界场景验证 |

## 四、测试策略说明

### 整体策略

1. **正向流程优先：** 先覆盖商品列表查看、新增、编辑、上下架、搜索的完整正向路径
2. **字段校验其次：** 覆盖新增/编辑表单的必填校验、边界值、格式约束
3. **分支与异常补充：** 覆盖搜索+筛选组合、规格联动、图片约束等分支场景
4. **权限兜底：** 验证非管理员角色的访问拦截
5. **探索性场景标记：** 无已验证事实支撑的场景（如确认弹窗、删除功能）标记为探索性

### 场景分组

| 场景组 | 场景数 | 说明 |
|--------|--------|------|
| 列表查看 | 2 | 正向查看 + 分页 |
| 新增商品 | 6 | 正向新增 + 必填校验 + 图片约束 + 无规格 + 大规格 + 字段边界 |
| 编辑商品 | 4 | 正向编辑 + 规格联动 + 图片操作 + 数据回显 |
| 上下架 | 3 | 下架执行 + 下架确认探查 + 上架执行 |
| 搜索筛选 | 3 | 搜索 + 状态筛选 + 组合筛选 |
| 权限控制 | 3 | 普通用户 + 禁用用户 + 未登录 |
| 前后台一致性 | 1 | 下架后前台不可见 |
| 探索性 | 3 | 确认弹窗、删除功能、规格删除联动 |

### 不确定预期的处理方式

对于待确认问题（C-01 ~ C-12），采用以下策略：
- **有候选预期的：** 写入正式场景，预期部分标注"候选预期"
- **无任何预期的：** 写入探索性场景，描述验证路径
- **与文档矛盾的：** 同时记录文档预期和实测行为，由产品/开发确认
