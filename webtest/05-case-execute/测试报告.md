## 两大核心 Bug 最终定性

### Bug①：订单详情收货信息为空
- **严重度：** 高
- **类型：** 前端显示缺陷
- **复现步骤：**
  1. buyer1 登录
  2. 选择商品加入购物车 → 结算 → 选择地址 → 提交订单
  3. 进入订单详情页
- **现象：** 收货人、手机号、收货地址字段为空
- **根因：** API `GET /api/orders/:id` 返回的 JSON 中 `addressSnapshot` 字段包含完整地址数据（name, phone, province, city, district, detail），但前端未渲染该字段
- **证据：** API 响应确认 addressSnapshot 存在且有值，页面字段为空
- **影响：** 所有订单的收货信息均无法在详情页查看

### Bug②：后台订单操作列为空
- **严重度：** 高
- **类型：** 前端条件渲染缺陷
- **复现步骤：**
  1. admin 登录后台
  2. 进入订单管理页面
  3. 观察任意订单行的操作列
- **现象：** 所有订单行的操作列为空，无任何按钮（发货、退款等）
- **根因：** 前端操作列的条件渲染逻辑存在缺陷。已通过 API 验证订单状态迁移正常（pay/ship/confirm/refund 端点均可用），但前端未根据订单状态渲染对应操作按钮
- **证据：** 截图显示操作列 header 存在，但所有行的 cell 为空
- **影响：** 管理员无法通过后台界面执行任何订单操作（发货、退款等），只能通过 API 操作

#### F-TC-013：🔴 库存为0时商品详情页崩溃
- **状态：** 失败
- **严重度：** 高
- **执行步骤：** 通过 API 创建库存为0的测试商品（id=27, name="测试商品-零库存", stock=0, status="on"）→ buyer1 登录 → 访问 /product/27

- **根因定性：** **前端组件异常** — 零库存商品的数量选择器 InputNumber 组件因 min(1) > max(0) 抛出异常，导致整个商品详情页无法渲染。应加防护：当库存为0时禁用数量选择器或显示"暂时缺货"提示
