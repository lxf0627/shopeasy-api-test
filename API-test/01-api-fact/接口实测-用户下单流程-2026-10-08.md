## 1. 业务目标

### 1.1 业务背景
本次采集围绕电商平台的**用户下单流程**，验证从用户登录到订单完成的完整业务链路。

### 1.2 业务路径
```
登录 → 商品详情 → 选择规格 → 加入购物车 → 购物车结算 → 创建订单 → 查询订单
```

### 1.3 操作边界
- ✅ 可以创建演示订单
- ❌ 不进入支付宝、微信、银行卡等第三方真实支付
- ✅ 默认走"加入购物车后结算"，不走"立即购买"
- ✅ 默认不使用优惠券
- ✅ 使用货到付款（模拟支付）方式

### 1.4 成功标准
- 能完成从商品选择到创建订单
- 能在系统中查询到新建订单
- 商品选择不同规格后价格显示正确

### 3.6 添加购物车

**基本信息**
- 方法: `POST`
- 路径: `/api/cart`
- 认证: 需要登录
- Content-Type: `application/json`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| productId | integer | ✅ | 商品ID |
| skuId | integer | 条件必填 | 有规格商品必填 |
| quantity | integer | 否 | 数量，默认1 |

**请求示例**
```bash
curl -s -X POST -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"productId":1,"skuId":1,"quantity":1}' \
  "http://localhost:3000/api/cart"
```

**响应示例**
```json
{
  "code": 201,
  "message": "已加入购物车",
  "data": {
    "id": 3,
    "userId": 2,
    "productId": 1,
    "skuId": 1,
    "specText": "256GB / 原色钛金属",
    "quantity": 1,
    "selected": true
  }
}
```

**业务规则:**
- 同一商品+同一SKU已存在时，累加数量
- 有规格商品必须传 skuId
- 新加入的购物车项默认 selected: true

### 3.7 创建订单

**基本信息**
- 方法: `POST`
- 路径: `/api/orders`
- 认证: 需要登录
- Content-Type: `application/json`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| addressId | integer | ✅ | 收货地址ID |
| remark | string | 否 | 订单备注 |
| couponId | integer | 否 | 优惠券ID |

**请求示例**
```bash
curl -s -X POST -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"addressId":1,"remark":"测试订单"}' \
  "http://localhost:3000/api/orders"
```

**响应示例**
```json
{
  "code": 201,
  "message": "订单创建成功",
  "data": {
    "id": 26,
    "orderNo": "ORD17914324575466T6X",
    "userId": 2,
    "totalAmount": 9999,
    "status": "pending",
    "addressSnapshot": "{...}",
    "remark": "测试订单",
    "createdAt": "2026-10-08T04:07:37.546Z"
  }
}
```

**业务规则:**
- 从购物车中取所有 `selected: true` 的商品
- 自动生成订单号：`ORD` + 时间戳 + 随机字符
- 创建订单后清空已选购物车项

**后续依赖:**
- `data.id` 用于订单支付、查询
- `data.orderNo` 用于订单号展示

## 4. 业务请求链

### 4.1 完整下单流程

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                    用户下单流程请求链                                              │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                  │
│  ① 登录                              ② 商品浏览                      ③ 加入购物车                 │
│  POST /api/auth/login                GET /api/products               POST /api/cart              │
│  → token                             GET /api/products/:id           ← cartItemId                │
│                                      → skuId                                                  │
│                                                                                                  │
│  ④ 查询地址                          ⑤ 创建订单                      ⑥ 订单支付                   │
│  GET /api/addresses                  POST /api/orders                POST /api/orders/:id/pay    │
│  → addressId                         → orderId                       → status: paid              │
│                                                                                                  │
│  ⑦ 管理员发货                        ⑧ 用户确认收货                  ⑨ 订单查询                   │
│  PUT /api/admin/orders/:id/ship      PUT /api/orders/:id/confirm     GET /api/orders/:id         │
│  → status: shipped                   → status: received              → 完整订单信息              │
│                                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 订单状态流转

```
pending（待支付）
    │
    ├── → paid（已支付）──→ shipped（已发货）──→ received（已确认收货）
    │
    └── → cancelled（已取消）
```

## 6. 文档差异

### 6.1 已发现差异

| 序号 | 接口 | 文档描述 | 实际运行 | 影响 |
|------|------|----------|----------|------|
| 1 | POST /api/orders | remark字段支持中文 | 实际返回乱码"Զ" | ⚠️ 编码问题 |
| 2 | GET /api/orders/:id | addressSnapshot为对象 | 列表接口返回JSON字符串 | ⚠️ 格式不一致 |

### 6.2 说明

1. **remark字段编码问题**: 创建订单时传入中文备注"测试订单"，响应中显示为乱码。可能是服务端字符编码配置问题。

2. **addressSnapshot格式差异**:
   - 订单详情接口（GET /api/orders/:id）返回已解析的对象
   - 订单列表接口（GET /api/orders）返回JSON字符串
   - 与文档描述一致，但前端需要兼容两种格式
