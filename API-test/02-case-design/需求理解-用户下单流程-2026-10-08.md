## 1. 业务背景

### 1.1 业务目标
验证电商平台用户从登录到完成订单的完整购买流程，确保核心交易链路的正确性和稳定性。

### 1.2 核心业务路径
```
用户登录 → 浏览商品 → 选择规格 → 加入购物车 → 结算下单 → 订单支付 → 等待发货 → 确认收货
```

### 1.3 业务价值
- 保障用户能够顺利完成商品购买
- 确保订单状态流转正确
- 验证库存扣减和恢复机制
- 确保支付流程（模拟）正常

## 5. 业务规则

### 5.1 订单创建规则
- 必须选择收货地址
- 从购物车中取所有 `selected: true` 的商品
- 有规格商品必须选择SKU
- 库存不足时拒绝创建
- 自动生成订单号：`ORD` + 时间戳 + 随机字符
- 创建订单后清空已选购物车项

### 5.2 订单状态流转规则
```
pending（待支付）
    ├── → paid（已支付）──→ shipped（已发货）──→ received（已确认收货）
    └── → cancelled（已取消）
```

**状态转换限制：**

| 当前状态 | 可执行操作 | 目标状态 |
|----------|-----------|----------|
| pending | 支付 | paid |
| pending | 取消 | cancelled |
| paid | 发货 | shipped |
| shipped | 确认收货 | received |

### 5.3 库存规则
- 创建订单时扣减库存
- 取消订单时恢复库存
- 库存为0的商品不能加入购物车
