## 2. 确定性场景

### 2.1 正向场景

#### TC-POS-001: 用户完整下单流程（购物车路径）

| 项目 | 内容 |
|------|------|
| **场景描述** | 用户登录后，将有规格商品加入购物车，创建订单并支付 |
| **覆盖测试点** | TP-POS-001, TP-POS-002, TP-POS-003 |
| **优先级** | P0 |

**前置条件**
- 测试账号 buyer1 可用
- 商品 iPhone 15 Pro Max (id=1) 在售且有库存
- buyer1 有默认收货地址 (id=1)

**测试步骤**

| 步骤 | 操作 | 接口 | 请求参数 |
|------|------|------|----------|
| 1 | 用户登录 | POST /api/auth/login | `{"username":"buyer1","password":"123456"}` |
| 2 | 获取商品详情 | GET /api/products/1 | - |
| 3 | 添加到购物车 | POST /api/cart | `{"productId":1,"skuId":1,"quantity":1}` |
| 4 | 查询购物车 | GET /api/cart | - |
| 5 | 创建订单 | POST /api/orders | `{"addressId":1}` |
| 6 | 查询订单详情 | GET /api/orders/{orderId} | - |

**预期结果**

| 步骤 | 预期 |
|------|------|
| 1 | code=200, 返回token和用户信息 |
| 2 | code=200, 返回商品详情含specGroups和skus |
| 3 | code=201, message="已加入购物车" |
| 4 | code=200, 购物车包含刚添加的商品，selected=true |
| 5 | code=201, status="pending", totalAmount=9999 |
| 6 | code=200, 订单详情包含OrderItems和addressSnapshot |

**数据清理**
- 清理本轮创建的购物车项（如果步骤5失败）
- 订单数据保留用于后续场景

#### TC-POS-002: 完整订单状态流转

| 项目 | 内容 |
|------|------|
| **场景描述** | 订单从pending状态经过支付、发货、确认收货完成全流程 |
| **覆盖测试点** | TP-POS-004 |
| **优先级** | P0 |

**前置条件**
- 存在pending状态的订单（依赖TC-POS-001创建的订单）

**测试步骤**

| 步骤 | 操作 | 接口 | 请求参数 |
|------|------|------|----------|
| 1 | 用户登录 | POST /api/auth/login | `{"username":"buyer1","password":"123456"}` |
| 2 | 订单支付 | POST /api/orders/{id}/pay | `{"method":"balance"}` |
| 3 | 管理员登录 | POST /api/auth/login | `{"username":"admin","password":"123456"}` |
| 4 | 管理员发货 | PUT /api/admin/orders/{id}/ship | - |
| 5 | 用户确认收货 | PUT /api/orders/{id}/confirm | - |
| 6 | 查询订单详情 | GET /api/orders/{id} | - |

**预期结果**

| 步骤 | 预期 |
|------|------|
| 1 | code=200, 获取buyer1的token |
| 2 | code=200, status="paid", payTime有值 |
| 3 | code=200, 获取admin的token |
| 4 | code=200, status="shipped", shipTime有值 |
| 5 | code=200, status="received", receiveTime有值 |
| 6 | code=200, 订单最终状态为received |
